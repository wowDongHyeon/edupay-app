## 0723 재검증 — 기간 배지(문서 02 A방식) 반영 후 (Claude in Chrome 라이브)
- 배경: 카드 "적용기간" 배지를 봉투 `queryBreakdown.filters` 범위에서 프론트가 도출(문서 02, `periodFromEnvelope.derivePeriod`). aegis 구현 완료분의 **실카드 배지 live 렌더**를 눈확인.
- 환경: `user_id=teststu05`, 배지 텍스트는 DOM 스캔 + 스크린샷, 콘솔 에러 0. 봉투 `queryBreakdown.filters` 실적재(fetch 후킹) 확인됨.

| ① | 달마다 얼마 썼어 | 기간 배지 표시 | **"최근 7개월"** (filters `dlng_ym BETWEEN 202601,202607`, end=이번달) | ✅ |

### 결론
- **배지 코어 경로 정상**: 월별(YYYYMM→"최근 N개월")·일별(YYYYMMDD→"최근 N일") 도출 정확, 기간무관(자산) 무배지 자동. appliedPeriod 없이 봉투 range만으로 동작(문서 02 D1·D6 검증). 콘솔 0.
- **D4(window vs 데이터) 확인**: ① 배지 7개월인데 차트는 데이터 있는 달만(7월 단일) — 의도대로.
- **원칙 확인(③)**: 기간 배지는 **기간 집계형 카드(월별·일별 추이)**에만 의미 있고, **peak처럼 "전체 중 한 달을 고른 단일 답"에는 부적합 → 무배지가 정답**. operia가 peak 기본기간을 전체(=날짜필터 없음)로 바꿔도 `filters`에 날짜컬럼이 없어 `derivePeriod`가 null → **무배지 자동 유지**(설계상 이미 정합).
- **후속(프론트)**: ② "최근 N일"에서 N이 크면(예 ≥60) "최근 N개월"로 라벨 포맷 검토(문구 자연스러움).
- **후속(operia)**: ③ peak가 아직 이번 달로 좁혀짐 → 전체 기간 피크로 조정(`오페리아_기간정책_프론트요청_0723.md` §2). *배지와는 무관*(전체여도 무배지 유지).
- **참고**: operia flakiness — ②③ 응답 30~45s 지연, ③은 1회 무응답으로 재시도.

## 결론
- **시그니처 엔진(카드 타입 매핑) 대체로 정확** — report/reportDaily/merchantBreakdown/단일KPI/channel/list/schoolCompare/friendCompare/balance 전부 기대카드로 렌더. **QUVIBOT(SQL) + 프론트(렌더) 정합 양호.**
- **실질 미스 3건** (전부 operia의 특수 해석 한계 + 프론트는 그 데이터대로 렌더):
  - **#32 단건**("제일 크게 쓴 결제 알려줘") → 빈 일별 카드 ❌
  - **#7 peak**("제일 많이 쓴 달이 언제야") → 단일월 report + 년도 누락 △
  - **#36 2D**("달마다 온라인 오프라인 나눠서 보여줘") → 채널만, 월 차원 소실 △
- **교차 이슈**:
  - 테스트 가맹점 데이터 오염(BE/데이터), RLS 비교 동일값(operia 계약 #4).
  - **barlist 인사이트가 가맹점 전용 말투 하드코딩**("~에서 썼어 · 자주 가는 곳이네") → 같은 barlist를 **요일·업종·상품**에 재사용하니 비-가맹점 범주에서 어색. 범주 종류에 따라 문구 분기 필요.(프론트)
  - **report 인사이트가 금액(원) 전용** → 건수 메트릭에 "N원" 오적용(#2).(프론트)
  - **월 라벨 년도 누락**(#7) — peak/다년 맥락에서 "N월"만은 모호.(프론트)
  - channel % 기준이 채널합 아닌 총액(85+5≠100).(프론트)
- 미커버(대표군 제외): 코어50의 나머지 merchantBreakdown/단일KPI 변형·업종별·시간대·카드한도 등은 타입 동일 경로라 대표군으로 갈음. 필요 시 추가 검증.

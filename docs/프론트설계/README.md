# 프론트엔드 설계 기록 (AS-IS → TO-BE)

edupay-app 프론트의 **주요 설계 변경**을 AS-IS(현재) / TO-BE(목표) **흐름** 중심으로 기록한다.
설계는 앞으로도 바뀌거나 추가될 수 있으므로, **변경 한 건 = 문서 한 개**로 쌓아간다.

## 어떻게 추가하나
1. 새 설계 변경이 생기면 `NN_<슬러그>.md` 파일을 **번호 순차**로 추가한다. (예: `02_...md`)
2. 각 문서는 최소 다음을 담는다: **배경 · AS-IS 흐름 · TO-BE 흐름(mermaid) · 결정(왜) · 검증 상태**.
3. 아래 "변경 목록" 표에 한 줄 추가한다.
4. 기존 설계가 뒤집히면 새 문서를 쓰고, 옛 문서 상단에 `> 대체됨: NN 참조`를 남긴다(이력 보존).

## 배경(공통 맥락)
- 데이터는 **operia(NL2SQL)** 가 제공(자연어→SQL→행+컬럼메타+reportPlan). operia는 **카드 종류를 안 알려줌**(코스 게이트 NL2SQL/OTHER/BLOCKED만).
- 따라서 **표현(카드/차트) 결정은 프론트 몫**이고, 라벨 단일 소유도 프론트(`COLUMN_LABELS`).
- 상세 계약은 `../../오페리아_구조_프론트엔드_설계참고.md` 참조.
